# Переезд на российский хостинг: сайт, форма, почта на домене

Цель: сайт и заявки работают без VPN из любой российской сети, быстрее открываются для Яндекса, а адреса вида `info@baikalresearch.ru` живут на своем домене. Адреса страниц не меняются (домен тот же), поэтому редиректы и «переезд сайта» в Вебмастере не нужны.

## Что где будет

| Что | Сейчас | После переезда |
|---|---|---|
| Сайт | GitHub Pages (Финляндия) | Российский хостинг с PHP (например, у Reg.ru, где уже домен) |
| Форма заявок | внешний сервис | `/api/lead.php` на том же хостинге (запасным остается Worker) |
| Почта на домене | нет | ящики `info@baikalresearch.ru` у Reg.ru или в Яндекс 360 для бизнеса |
| Исходники | GitHub | GitHub (не меняется), оттуда сайт сам выкладывается на хостинг |
| Telegram-боты | bothost | bothost (не трогаем) |

## Шаг 1. Выбрать хостинг (решение владельца)

Нужно: PHP 8.1 или новее, бесплатный сертификат Let's Encrypt, доступ по FTP/FTPS, ящики на домене, исходящие запросы (curl) к `api.telegram.org`. Подойдет обычный хостинг у Reg.ru: домен уже там, DNS и сертификат настраиваются в одном кабинете. Актуальные тарифы смотрите на reg.ru. Если хочется больше свободы, вместо хостинга берут VPS (nginx вместо `.htaccess`), но для статического сайта это избыточно.

## Шаг 2. Подготовить хостинг

1. Заказать хостинг, привязать домен `baikalresearch.ru` (и `www`).
2. Выпустить сертификат Let's Encrypt.
3. Узнать FTP-данные: сервер, логин, пароль, папка сайта (обычно `www/baikalresearch.ru` или `public_html`).
4. В папке **на уровень выше папки сайта** создать файл `lead.config.php` по образцу `server/lead.config.example.php` (токен бота и chat id). В репозиторий этот файл не кладем.

## Шаг 3. Подключить автоматическую выкладку

В репозитории GitHub: Settings → Secrets and variables → Actions → New repository secret. Добавить: `RU_FTP_HOST`, `RU_FTP_USER`, `RU_FTP_PASSWORD`, `RU_FTP_DIR` (папка сайта, например `/www/baikalresearch.ru/`). Затем Actions → «Deploy to Russian hosting» → Run workflow. Он соберет сайт, добавит `.htaccess` и `api/lead.php` и зальет на хостинг.

Когда все проверено, в файле `.github/workflows/deploy-ru.yml` блок `on:` заменить на запуск при каждом push в `main`.

## Шаг 4. Проверить до переключения

Открыть сайт по техническому адресу хостинга (его дает Reg.ru) или временно прописать IP в файле hosts на компьютере. Проверить: страницы открываются, картинки и шрифты грузятся, 404-страница есть, форма отправляет заявку (придет в Telegram и на почту), `https://…/robots.txt` и `sitemap-index.xml` открываются.

## Шаг 5. Переключить DNS

В кабинете Reg.ru (DNS-зона baikalresearch.ru):
1. За сутки до переезда уменьшить TTL записей до 300 секунд.
2. Записи `A` для `@` заменить на IP хостинга. `www` оформить как `CNAME` на `@` (или `A` на тот же IP).
3. GitHub Pages оставить рабочим: в первые дни он запасной.
4. Через несколько часов проверить `curl -I https://baikalresearch.ru/` (должен быть сервер хостинга, а не GitHub).

## Шаг 6. Подключить форму на российском адресе

В `src/config.js` задать `FORM_ENDPOINT_RU = '/api/lead.php'`. Форма будет сначала пробовать его (быстро и из любой сети), а при сбое пойдет в запасной внешний сервис. Проверить заявку с мобильного без VPN.

## Шаг 7. Почта на домене

Два варианта, выбрать один:
- **Почта Reg.ru на домене.** Ящики создаются в том же кабинете, записи MX настраиваются автоматически. Проще всего.
- **Яндекс 360 для бизнеса.** Привычный интерфейс и приложение Яндекс Почты. Нужно добавить домен, подтвердить его и прописать записи MX, SPF (TXT) и DKIM в DNS Reg.ru. Условия и лимиты бесплатного тарифа проверьте в Яндексе.

На старте настройте переадресацию `info@baikalresearch.ru` на `baikalresearch@yandex.ru`, чтобы ничего не потерять. В описании организации и на сайте адрес можно будет заменить на `info@…`, когда ящик заработает.

## Шаг 8. После переезда

1. Включить HSTS в `server/.htaccess` (строка закомментирована).
2. Проверить Search Console и Вебмастер: нет ли новых ошибок обхода.
3. Через неделю сравнить время ответа: у GitHub Pages из России оно скачет от 0,3 до 5 секунд, на российском хостинге должно быть стабильно быстрее.
4. Отключить запасной вариант (GitHub Pages, внешний сервис) только когда пройдет две недели без проблем.

## Откат

Вернуть записи `A` для `@` на адреса GitHub Pages (`185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`). Сайт снова будет открываться с GitHub.
