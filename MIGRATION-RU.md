# Как устроены хостинг, форма и почта

Сайт, прием заявок и почта на домене работают на российских серверах, поэтому все открывается без VPN из любой сети.

## Что где находится

| Что | Где |
|---|---|
| Сайт | Хостинг Reg.ru («Хост-А»), PHP 8.3, сертификат Let's Encrypt |
| Форма заявок | `/api/lead.php` на том же хостинге |
| Почта на домене | Ящики `@baikalresearch.ru` на том же хостинге, копия писем пересылается на личную почту |
| Исходники | GitHub, оттуда сайт сам выкладывается на хостинг |
| Telegram-боты | bothost |

## Выкладка

Каждый push в ветку `main` запускает workflow «Deploy to Russian hosting» (`.github/workflows/deploy-ru.yml`): сборка, добавление `server/.htaccess` и `server/api/lead.php`, загрузка по FTPS. Нужны секреты репозитория: `RU_FTP_HOST`, `RU_FTP_USER`, `RU_FTP_PASSWORD`, `RU_FTP_DIR`.

## Форма заявок

`lead.php` проверяет данные и отправляет заявку:
1. письмом через SMTP ящика (запасной канал `mail()`);
2. в Telegram с одним повтором.

Секреты лежат в файле `lead.config.php` на хостинге, на уровень выше папки сайта (образец: `server/lead.config.example.php`). В репозиторий этот файл не попадает. Журнал `lead.log` рядом с ним хранит только время и каналы доставки.

## DNS (Reg.ru, «Ресурсные записи»)

`A` для `@` и `www`: IP хостинга. `MX`: `mx1.hosting.reg.ru` (10), `mx2.hosting.reg.ru` (20). `TXT`: SPF на `@`, DKIM на `dkim._domainkey`, DMARC на `_dmarc`. Значение DKIM берется из панели хостинга.

## Регулярные проверки

- Сертификат продлевается автоматически, раз в несколько месяцев стоит убедиться в этом в панели хостинга.
- Доступность сайта проверяет `.github/workflows/uptime-check.yml` каждые 15 минут и пишет в Telegram при сбое.
- После переезда (через 2 недели без проблем) GitHub Pages можно отключить.
